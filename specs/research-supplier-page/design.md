The `seo-meta` feature had already moved `title`, `description`, `canonicalUrl`, `ogType`,

## Design decisions

| Decision | Choice | Rejected alternative |
|----------|--------|----------------------|
| Headline level | `<h1>` in the page body | `.section-title` `<h2>` — this page needs a real `h1` for SEO; the header logo is a `<span>` on the current base, so the page's `h1` is its only one |
| Numbered questions | `<ol>` with explicit number `<span>` per `<li>` | Native `list-decimal` markers — the global reset `* { margin:0; padding:0 }` in `global.css` collapses list padding and clips the markers |
| Content column | Scoped `.research-body { max-width: 48rem; margin-inline: auto }` | Tailwind `max-w-3xl mx-auto` — `mx-auto` is inert (see "CSS cascade gotcha" below) |
| Contact block | Plain links in a short paragraph | `.btn` CTA buttons — too close to a marketing landing page (R19) |
| Badge | Scoped `.research-badge` with a 1px `var(--primary-blue)` border | Tailwind `border px-2 py-0.5` — `padding-*`/`border` utilities are inert on this site |
| Background | `bg-surface` throughout | Alternating backgrounds — a single reading page; alternation adds noise |
| Nav label | "Research" (matches the English nav vocabulary) | "Lieferforschung" — inconsistent with Home/Publications/Projects/Blog/Wishlist |
| Layout props vs per-page `<head>` | Reuse upstream SEO props + one new `lang` prop | Duplicating `<head>` in the page — breaks the single-source-of-truth `Layout.astro` |
| Sitemap | Rely on `@astrojs/sitemap`, leave `public/sitemap.xml` deleted | Re-instating a hand-written sitemap — it would fight the generated one and contradict `seo-meta` |
| Router | `src/pages/research/supplier-data.astro` (file-based) | Dynamic `[...slug].astro` — one page does not justify dynamic routing |
| Hamburger visibility (R23) | `max-lg:flex` instead of `flex` on `#mobile-menu-btn` | Shrinking the homepage nav gap — would mask the symptom while leaving the hamburger visible on desktop for every page |

## CSS cascade gotcha (drives several choices above)

`src/styles/global.css` declares `* { margin: 0; padding: 0 }`, `p { margin-bottom }` and
`h1/h2/h3 { font-size }` **outside any CSS layer**, while Tailwind v4 puts its utilities in
`@layer utilities`. Unlayered declarations outrank layered ones, so **every `margin-*` /
`padding-*` utility site-wide is inert**, as is `text-*` on `h1`/`h2`.

Consequences accepted here:

- The page compensates with a small **scoped** `<style>` block (specificity ≥ (0,1,0), unlayered).
- Selectors inside it are deliberately disjoint (`.research-body > p|ul|ol|div`, `> h1`, `> h2`)
  because Astro rewrites bare element selectors to `element[data-astro-cid-…]`, which would
  otherwise out-specify a generic `> * + *` flow rule.
- `gap-*`, colour, `display`, `max-width` and font-family (by inheritance) do work, and are used.

## Same gotcha, opposite direction: R23

`#mobile-menu-btn` carries both `lg:hidden` and an unprefixed `flex`. In the built CSS,
`.flex{display:flex}` is emitted **after** `.lg\:hidden{display:none}`, so the hamburger
stayed visible at ≥1024px on every page of `origin/master`. Adding a 9th desktop nav item
(Research) then pushed the homepage to `scrollWidth 1031 > 1024`.

Swapping the unprefixed `flex` for `max-lg:flex` removes the overlap entirely: the two rules
can never both apply, so emission order stops mattering.

## Responsive behaviour

- Desktop (≥1024px): desktop nav shown, hamburger hidden (`none`), homepage carries 9 links
  (`scrollWidth 1024 = innerWidth`), subpages 6.
- Below 1024px: desktop nav hidden, hamburger shown and operable (`aria-expanded` toggling).
- Prose column is fluid inside `.container`; `.research-body` only caps at 48rem, never forcing
  horizontal scroll.
- Verified at 375 / 768 / 1024 / 1440 in headless Chromium with `scrollWidth ≤ innerWidth`
  on all 6 pages.

## Test coverage

`tests/smoke.test.ts` previously used a non-recursive `readdirSync`, so `src/pages/research/`
would have been silently skipped. It now walks recursively (6 pages covered), and the
`@astrojs/compiler` it imports is declared as a devDependency — pnpm's strict layout does not
hoist transitive dependencies, so the import failed on a clean install before that.

## Dependencies

No runtime dependency added. One devDependency (`@astrojs/compiler`, already transitively
present via `astro`, now declared) so the smoke test can import it directly.
